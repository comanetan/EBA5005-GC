# Forecasting interface for Daniel

## Install and use

Copy the `forecasting` package including `models/preliminary/manifest.json` and
`models/preliminary/fitted_model.pkl` into the shared repo. Include `__init__.py`,
`model_api.py` and the requirements files. Run from the repo root:

```powershell
python -m pip install -r forecasting/requirements-tested.txt
python -m forecasting.example_ui_call
```

Only load pickle model bundles generated by trusted team members. Use the recorded
Python/package versions. This is a Python function, not an HTTP endpoint; a JavaScript
UI would call it through its Python backend. No raw CSV or personal OneDrive path is
required for inference. Do not copy `.venv` or caches.

```python
from forecasting.model_api import Forecaster

forecaster = Forecaster()  # Load once when the application starts.
segments = forecaster.available_segments()
result = forecaster.predict(
    segment_id="SENGKANG::4 ROOM",
    horizon_months=12,
    confidence_level=0.90,
    # Optional illustrative input from pricing lead, dated to forecast origin:
    base_price_sgd=600000,
    base_price_month="2026-09",
)
rows = result["forecasts"]  # List of dictionaries; JSON serializable.
```

## Contract

- Horizon: integer 1-12. Forecast origin is fixed by the saved model, not today's date.
- Confidence: central interval level strictly between 0 and 1; default 0.90.
- Current bundle: only SENGKANG::4 ROOM, origin September 2026. Other segments fail explicitly.
- Each row: month, horizon, forecast_psm, lower_psm, upper_psm, growth_factor,
  growth_factor_lower, growth_factor_upper.
- PSM units: SGD per square metre of the monthly transaction-median proxy.
- Growth factor denominator: last observed segment median at the saved origin.
- Optional profile-price scenario: base price multiplied by the growth factor/bounds.
  Base price must be positive and refer to the same month as the model origin.
- Metadata: schema/model version, model name, origin, reference value, target,
  interval quantiles, preliminary status and limitations. Preserve these in the UI.
- A central 90% interval has a 95th-percentile upper endpoint, NOT a 90th-percentile
  endpoint. These bounds are not yet calibrated for an affordability chance constraint.

Budget, preference weights and minimum lease belong in the optimiser. Model orders
are chosen offline, not exposed as household sliders. The optional dollar scenario
assumes a profile follows segment movement; it excludes Comane's valuation uncertainty.

## Offline update

Run `python forecasting/preliminary_forecast.py` to retrain/evaluate and export a new
bundle. UI calls only load/predict; no retraining occurs. The training source defaults to the repository data/raw folder and can be overridden
with HDB_RESALE_CSV; the exported inference bundle is portable. The export supports
both the statistical model and either simple baseline if selected in a future run.

The current model remains ARIMA with drift selected on historical validation; packaging
does not improve its previously reported poor holdout coverage. Hedonic index integration,
external regressors, LSTM/SHAP and additional segments remain future work.

`simulate_paths()` deliberately raises NotImplementedError: joint temporal/cross-segment
simulation is not implemented. Do not generate Monte Carlo trajectories by independently
sampling each month's forecast interval.

## Verification

`python -m unittest forecasting.test_model_api -v`

Checks that reloaded predictions equal the training script's outputs, no fitting occurs
during predict(), horizon/confidence inputs work, optional dollar scaling is correct,
and unsupported segments/date mismatches fail clearly. Tests require the local outputs
from a completed training run; Daniel only needs the inference files for his UI.
